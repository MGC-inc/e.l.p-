# 週次MT議事録反映スキル

運用全体は [マニュアル/週次MT.md](../../../マニュアル/週次MT.md) と [マニュアル/リーダー会議.md](../../../マニュアル/リーダー会議.md)。
メンバーはMTの最後にLINE（ユメイク営業分析bot）で ①学び ②今週の宿題 ③数字の目標 を送る（📝週次PDCA記録DBに入る）。
このスキルは、**MTで実際に話して決めた内容（議事録）を正**として、LINEの内容との違いを直し、送り忘れを埋め、
先週の宿題の ◎○× を記録する。翌週のスライド①（答え合わせ・前回の評価）と⑥（みんなの学び）にそのまま載る。

## 手順（週次MT）

1. **議事録を探す**
   `mcp__Notion__notion-query-meeting-notes` で、対象の水曜（定期実行なら今日）に作成された議事録を探す。
   タイトルに「週次MT」を含むものを優先し、無ければその日の朝（JST 7:00〜12:00）に作成された議事録を
   `notion-fetch` で開き、宿題・◎○×・目標の話をしているものを週次MTとみなす。1日に複数（代理店ごと）あれば全部処理する。
   今川さんが議事録の本文やURLを直接渡した場合はそれを使う。
   **1件も無ければ何もせず終了する**（定期実行のときは通知もしない）。

2. **代理店とメンバーを確定する**
   議事録のタイトル・本文から代理店名を読む。メンバー名は Supabase `closer_line_users.closer_name`
   （= Notion「氏名」）の表記に合わせる（「林さん」→「林」）。表記が特定できない人は反映せず、手順6の報告に「名前を特定できず」と書く。

3. **1人ずつ抽出する**（議事録に出てこない項目は書かない＝推測で埋めない）
   - `evaluation`: 先週の宿題の評価。◎（やった＋数字が良くなった）／○（やったが数字はまだ）／×（やらなかった）。
     議事録に記号が無くても、話の内容から基準どおりに判断できる場合だけ入れる。迷う場合は入れずにnoteに書く
   - `evaluation_note`: 評価の根拠（いつ・誰と・何回やったか等）を1行
   - `action`: 今週の宿題（いつ・誰と・何を）
   - `targets`: 数字の目標。キーは `訪問数目標` `アポ数目標` `商談数目標_自アポ` `商談数目標_他アポ` `契約数目標_自アポ` `契約数目標_他アポ`
     （アポインターと、自アポ/他アポを分けずに言ったクローザーは `_自アポ` に入れる）
   - `learning`: 先週の振り返り・学び（1〜2行）
   - `note`: 上に入らないが残すべきこと（リーダーとの1対1が必要、など）

4. **抽出結果をJSONにして反映する**
   scratchpadに次の形で保存し、まず `--dry-run` で確認してから本実行する。
   ```json
   {"mt_date": "2026-10-21", "agency": "wanny", "minutes_url": "<議事録のURL>",
    "members": [{"name": "林", "evaluation": "○", "evaluation_note": "...", "action": "...",
                 "targets": {"訪問数目標": 60, "アポ数目標": 6}, "learning": "...", "note": "..."}]}
   ```
   ```bash
   python3 tools/shuuji/pdca_apply.py <json> --dry-run
   python3 tools/shuuji/pdca_apply.py <json> --notify   # 今川さんにLINEで結果を送る
   ```
   `pdca_apply.py` が、先週の行への◎○×記入、LINE未送信者の行の作成（記録元=議事録）、
   LINEと違う項目の上書き（記録元=LINE＋議事録で修正。LINE原文は元メッセージに残る）を行う。

5. **議事録をリポジトリにも残す**
   `議事録/YYYY/YYYY-MM-DD_<代理店>_週次MT.md` を `議事録/_template.md` の形で作る。
   決定事項＝各メンバーの宿題と数字、TODO＝note（1対1面談など）。Notionの議事録URLをメモに書く。
   コミットは `docs(議事録): YYYY-MM-DD <代理店>週次MT追加`。

6. **報告**
   `pdca_apply.py` の出力に加えて、次をまとめて報告する（定期実行のときは `--notify` のLINEで足りる。
   特定できなかった名前・判断に迷った評価があれば、それだけ追加で今川さんにLINEする）。
   - 2週続けて × の人（スライドの「前回の評価」と今回の評価から判断。マニュアルどおりリーダーの1対1が必要）
   - 2週続けて ○ の人（宿題の中身を変える必要がある）

## 手順（リーダー会議）

「リーダー会議の議事録を反映して」と言われたら、タイトルに「リーダー会議」を含む直近の議事録を読み、
各代理店の報告（数字・◎○×の人数・一番の課題・共有した1件）と「全社でやること」を抽出する。
`商談分析/YYYY/週次レビュー_YYYY-Wnn.md`（`商談分析/_週次レビューtemplate.md`）に記録し、
トークなど「やり方を変える」決定は `マニュアル/訪問営業.md` に反映する（どちらもコミットする）。
DBへの書き込みは無い。

## 注意

- 議事録に無いことを推測で書かない。LINEの内容を消すのは、議事録で明確に別の内容を決めた項目だけ
- 議事録はNotionのAIミーティングノート（今川さんのアカウント）から探す。代理店のリーダーが別の場所で
  議事録を取った場合は、今川さんに本文かURLを渡してもらう

# 営業マン登録管理スキル

営業マン（クローザー／アポインター／管理者）の新規登録・退社時削除を、確認は最小限（クローザー登録時の予算金額のみ）で最後まで一気に実行する。`scripts/add_closer.py`・`scripts/remove_closer.py`（時短ツール）に、これまで手動でやっていたNotion更新・git push・デプロイ確認までを1回の依頼にまとめたもの。

商談分析運用.md・`Claude操作マニュアル.md` セクション9の技術的な前提（自己登録フロー・KNOWN_*辞書・Supabaseの仕組み）はそのまま踏襲する。このスキルは「実行の手順」を定義する。

**ゴールマップ連携は現状保留中（ユーザー指示）**。`--goalmap`／`--remove-goalmap`は使わず、ゴールマップまわりには一切触れない。

## トリガー

- 「〇〇さんをクローザー（アポインター／管理者）として登録して」「〇〇さんを商談分析に登録して」「営業マンを追加して」
- 「〇〇さんが退社した」「商談分析から削除して」「〇〇さんを退社処理して」

全社共通の従業員登録（内線・タスク等）が目的なら、これとは別に `elp-goals` の `/staff` を案内する（このスキルの対象外）。

## 最初に確認すること（最初の返信で1回だけ、まとめて聞く）

依頼を受けたら、作業に入る前に**足りない情報を1回の返信にまとめて**聞く。聞いた後は最後まで止まらず、1回で完了させる（今川さん指示 2026-11-02）。依頼文で分かるものは聞かない。

- 苗字（必須）と、分かればフルネーム・読み（表記ゆれ対応と名簿DB用）
- 役割: クローザー／アポインター／アポ兼クローザー／管理者
- 所属（代理店名・個人事業主・自社）。新しい会社名なら、各DBの選択肢にその名前で追加してよいか
- 稼働開始日（初日報の日）と、研修・時短など特例があるか
- 今月の予算（万円）。「予算なし」なら0万円で行を作る。月次配分と一緒に決める場合は、行だけ0万円で作って後で更新する
- クローザーの場合のみ: アポ兼クローザーか、クローザー開始日

聞き忘れ防止: 次の「全DBの反映先」の表を見て、埋められない欄があれば、その場で聞く。

## 手順（追加）

1. `python3 scripts/add_closer.py <苗字> [--full-name "<姓 名>"] [--role closer|appointer|admin] [--agency "<会社名>"]` を実行する（`--goalmap`は付けない）。上の表の1・2が終わる。複数人なら人数分実行する。
2. 上の表の4〜9を、Notion MCP（`notion-fetch` → `notion-update-data-source` → `notion-create-pages`）で反映する。select列の追加を先にまとめて実行し、そのあとで行を作る（名簿DBの行を先に作り、そのURLをKPIの行のメンバーマスタに入れる）。
3. `line-webhook/api/webhook.py`・`従業員.md`をgit commit・pushする。
4. `line-webhook/`配下が含まれるので、Vercelプロジェクト`e-l-p`（team: `iyiyiyi`）の本番デプロイを`mcp__Vercel__create_deployment`で実行する（`requestBody`に`name`・`project`・`target: "production"`・`gitSource`（type/org/repo/ref/sha）・`projectSettings.rootDirectory: "line-webhook"`。`slug: "iyiyiyi"`）。`get_deployment`でREADYを確認する。
5. 完了報告を1メッセージで行う。反映先を上の表の番号で一覧にし、「できていないこと」と「本人にやってもらうこと」（Botへの最初のメッセージなど）を最後に書く。

## 手順（削除・退社時）

1. `python3 scripts/remove_closer.py <苗字>` を実行する（`--remove-goalmap`は付けない。ゴールマップは保留中でそもそも作られていない前提）
   - webhook.pyのKNOWN_*辞書・Supabaseの行・従業員.mdの行が削除される
2. Notion「💰 予算と達成率」(`collection://b1809b1a-e82d-4032-ac86-a32d165d475d`)を、`メンバー = <苗字>` かつ `年月（YYYY-MM）` が実行月より後の行がないかSQLで確認し、あれば`mcp__Notion__notion-move-pages`でtrashに移す（過去分・当月分は残す。停止し忘れ防止の自動化）
3. `line-webhook/api/webhook.py`・`従業員.md`の差分をgit commit・push する
4. 手順（追加）の5と同様に、Vercelデプロイが追従しているか確認し、必要なら明示的にデプロイする
5. 完了報告を1メッセージで簡潔に行う

## やらないこと（意図的）

- ゴールマップ連携（現状保留。ユーザーから明示的な指示があれば別途対応する）
- Notion「DB 商談分析＆アポ分析」の選択肢からの削除（既存の過去ページがその選択肢を参照しているため、追加のみ行い削除はしない。`scripts/remove_closer.py`のコメント方針を踏襲）
- 過去のNotionデータ・録音・分析結果の削除

## 注意

- 自動で判明しない情報（クローザーの予算金額）だけを最初にまとめて質問し、それ以外は都度確認しない（効率重視のユーザー指示）
- git pushは本番LINE Webhookに直結する。`line-webhook/`配下に変更がある回は、pushして終わりにせず必ずVercelデプロイの追従確認まで行う
- Notionのselect列を更新する際は、必ず直前に最新のoptions一覧を取得してから全件を含めて書き換える（既存options消失を防ぐため、古いスキーマ情報をキャッシュして使い回さない）

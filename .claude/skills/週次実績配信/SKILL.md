# 週次実績配信スキル

クローザー・アポインター全員（`closer_line_users` に `role` が設定されている人）へ、
週次の実績と月間チーム予算の進捗をLINEで配信する。**週1回（毎週月曜9:00 JST予定のRoutine、
または今川さんの「週次配信して」の指示）で実行する。**

商談録音分析スキル（`.claude/skills/商談録音分析/SKILL.md`）とは別物。あちらは「録音を分析した
その週のクローザー向け」の配信で、今川さんの指示（「商談録音を分析して」）でのみ動く。
このスキルは録音の有無に関係なく、**登録済み全員に定期的に数字とゴール進捗を届ける**もの。

## 対象者とデータソース

- **対象者**: Supabase `closer_line_users` で `role` が `closer` または `appointer` の行
  （`line_user_id`・`closer_name`・`role`・`goalmap_member_name`）
- **週次の商談・アポ実績**: Notion データソース `collection://8958bbaf-2c24-4e94-97b2-4c801e60cb37`
  （「DB 商談分析＆アポ分析」＝ E.L.P.md にある「今月の契約案件一覧」データソース）
- **月間チーム予算**: Notion データソース `collection://b1809b1a-e82d-4032-ac86-a32d165d475d`
  （「💰 予算と達成率」）。メンバーごとに月次の `予算（万円）` と、リレーション先の
  実績DBからロールアップした `実質売上合計（万円）` を持つ
- **個人目標の定性進捗**: `tools/goalmap/members/<closer_nameまたはgoalmap_member_name>.json`
  （ファイルが無い人は省略。達成率の式は `ゴールマップ運用.md` と同じ：
  現在フェーズの `done:true` タスク数 ÷ 全タスク数 × 100）

## 手順

1. **対象期間を計算する**：実行日（通常は月曜）を基準に、直近の月〜日を「先週」、
   その前の月〜日を「先々週」とする。月間予算は実行月（YYYY-MM）を使う。

2. **Supabaseから対象者を取得する**
   `closer_line_users?role=not.is.null&select=*` をPostgREST経由で取得する
   （`Claude操作マニュアル.md` §2 のPythonスニペットのパターン。`ELP_SUPABASE_URL`／
   `ELP_SUPABASE_SERVICE_ROLE_KEY` は環境変数から。値が全角括弧で囲まれて渡ってくることが
   あるので `.strip("（）()")` で防御する）。0件なら何もせず終了する。

3. **週次の商談・アポ実績を集計する（アポインター向け）**
   Notionデータソース `collection://8958bbaf-2c24-4e94-97b2-4c801e60cb37` を
   `mcp__Notion__notion-query-data-sources`（SQLモード）で、`アポインター` にその人の名前を含み
   `商談日時` が先週／先々週の範囲に入る行を集計する。
   - **商談数（訪問数）** = `結果` が `商談予定` 以外の件数（実際に商談が行われた数）
   - **アポ数** = `結果` を問わない全件数（`商談予定` も含む＝設定されたアポ全体）
   - 先週の各数値を、先々週の値との差分（＋n／−n）で添える
   ※この定義はNotion側に「訪問数」を独立して記録する項目がないための近似。実態と違う場合は
   今川さんに確認して本ファイルを更新する。

4. **月間チーム予算の進捗を集計する（全員向け・共通の1本）**
   Notionデータソース `collection://b1809b1a-e82d-4032-ac86-a32d165d475d` を
   `年月（YYYY-MM）` = 実行月で絞り、`予算（万円）` と `実質売上合計（万円）` をSUMする
   （`催事` など個人に紐付かない行も合算に含める。`予算（万円）` が空の行はSUMから除く）。
   達成率 = 実質売上合計 ÷ 予算合計 × 100（%、整数）。

5. **個人目標の定性進捗を読む（goalmapファイルがある人のみ）**
   `tools/goalmap/members/<name>.json` を読み、`currentStage` が指すフェーズ名、
   達成率（そのフェーズの `tasks` のうち `done:true` の割合×100）、`due` が実行日より前かつ
   未達成なら期限超過、を求める（`generate_goalmap.py`・商談録音分析スキルの手順6bと同じ式）。
   ファイルが無い人はこの項目を省略する。

6. **1人1通でLINE送信する**
   `DEAL_LINE_CHANNEL_ACCESS_TOKEN` を使い、`https://api.line.me/v2/bot/message/push` に
   POSTする（`scripts/line_richmenu.py` のurllib直叩きパターンを踏襲）。全員分を1回のバッチで
   送るが、**1人につき1回のpush呼び出し**に収める。

   **role='appointer' の人**:
   ```
   【週次実績】〇〇さん（<先週の月>/<日>〜<日>）
   訪問数: n件（先週比 +/-n）
   アポ数: n件（先週比 +/-n）
   ---
   📊 チームMTD予算進捗: 実質売上合計/予算合計万円（達成率%）
   （goalmapがあれば）現在フェーズ: ①<フェーズ名>（達成率n%）／期限超過なら⚠表示
   ```

   **role='closer' の人**:
   ```
   【週次実績】〇〇さん（<先週の月>/<日>〜<日>）
   （goalmapがあれば）現在フェーズ: ①<フェーズ名>（達成率n%）／期限超過なら⚠表示
   ---
   📊 チームMTD予算進捗: 実質売上合計/予算合計万円（達成率%）
   ```
   クローザーは商談録音分析スキル側で商談結果の詳細を別途受け取るため、ここでは
   ゴールマップ進捗＋チーム予算のみとする（数字の重複配信を避ける）。

7. **今川さんへの管理者サマリー**
   全員への配信が終わったら、今川さん（LINE）へ1通、対象者数・送信成功数・
   goalmap未整備で進捗を省略した人の一覧を送る（`scripts/add_closer.py --goalmap` で
   雛形を作れることも添える）。

## 注意事項

- 個人の売上・給与に関わる実数（`予算（万円）`・`実質売上合計（万円）`）は**チーム合計のみ**を
  配信する。個人別の予算達成率をアポインター・クローザー本人以外に見える形で配信しない
  （Notion上の個人別データはそのまま今川さんが確認できるので、配信では集約値のみ扱う）
- goalmapファイルが無い人（本スキル導入時点: 柚木・福本・巻田・林・安達・平井・山川・田村）は
  ゴールマップ進捗の行を省略してよい。今川さんが `tools/goalmap/members/_template.json` を
  元に内容を詰めたら自動的に反映される
- 「訪問数」「アポ数」の定義（手順3）はデータソースの制約による近似。もし正確な訪問数を
  別途（LINE日報等）記録している場合は、そちらを参照するよう本ファイルを更新する

# 週次実績配信スキル

クローザー・アポインター全員（`closer_line_users` に `role` が設定されている人）へ、
週次の実績とKPI目標、チーム予算進捗をLINEで配信する。**毎週水曜9:00 JST のRoutineで自動実行**
される（水曜朝にデータが安定するため。前日火曜夜時点ではNotionへの日次実績反映にラグがあり
不安定なことを実データで確認済み）。今川さんが「週次配信して」と指示した場合は手動でも実行する。

商談録音分析スキル（`.claude/skills/商談録音分析/SKILL.md`）とは別物。あちらは「録音を分析した
その週のクローザー向け」の配信で、今川さんの指示でのみ動く。このスキルは録音の有無に関係なく、
**登録済み全員に定期的に実績・KPI・チーム予算を届ける**もの。

## 対象週

**水曜始まり火曜終わり**（前回配信の翌日〜今回配信の前日）。例: 水曜9:00に配信する回は、
先々週水曜〜先週火曜の7日間（`実績日`ベース）を対象とする。

## 対象者とデータソース

- **対象者**: Supabase `closer_line_users` で `role` が `closer` または `appointer` の行
  （`line_user_id`・`closer_name`・`role`）
- **日次実績の事実**（訪問数・アポ数・契約・契約金額など）:
  Notion データソース `collection://f11afda4-a39d-4139-8e12-817d3f70267b`
  （「📉 営業部 実績DB」。LINEの `/shoudannhoukoku` 等の日報コマンドが書き込む、メンバー×日付の
  生データ。`予算と達成率`DBのロールアップ値はAPI経由で解決できない実装上の制約があるため、
  金額・達成率は必ずこの実績DBの生フィールドから自分で計算する）
  - `訪問数`・`アポ数`・`契約`・`保留`・`失注`・`クーリン`・`審査落`・`AC数`・
    `契約金額（万円）`・`キャンセル金額（万円）` を使う（列名はすべて全角）
  - `商談数` = 契約+保留+失注+クーリン+審査落+AC数（SQLモードでは `商談数` という計算済み列は
    `notAvailableInQuerySql` のため使えない。上記の生列から自分で合算する）
  - `実質売上（万円）` = 契約金額（万円） − キャンセル金額（万円）（これもSQL不可の計算列なので
    自分で計算する）
- **自アポ／他アポの区別**（クローザーのみ）:
  Notion データソース `collection://8958bbaf-2c24-4e94-97b2-4c801e60cb37`
  （「DB 商談分析＆アポ分析」）の対象週の行を、その人が `クローザー` の行についてカウントする。
  `アポインター` = 本人名なら「自アポ」、それ以外なら「他アポ」
  （注意: 実績DBの日次集計と、このDBの個別商談の日付・区分が数日ズレて記録されることがある。
  対象週で件数を突き合わせ、大きくズレる場合は実績DB側の件数を正として報告し、
  自アポ／他アポの内訳のみこのDBを参考値として使う）
- **月間予算**: Notion データソース `collection://b1809b1a-e82d-4032-ac86-a32d165d475d`
  （「💰 予算と達成率」）の `予算（万円）` 列を実行月でSUMする（`メンバー` ごとの行。
  `予算（万円）` が空の行はSUMから除く）

## 手順

1. **対象週を計算する**：実行日（水曜）を基準に、前週水曜〜前々週火曜ではなく
   「直近の火曜」を週末とする7日間（水曜始まり）を対象とする。月間KPI計算には実行月
   （YYYY-MM）のMTD（月初〜直近の実績日）を使う。

2. **Supabaseから対象者を取得する**
   `closer_line_users?role=not.is.null&select=*` をPostgREST経由で取得する
   （`Claude操作マニュアル.md` §2 のPythonスニペットのパターン。`ELP_SUPABASE_URL`／
   `ELP_SUPABASE_SERVICE_ROLE_KEY` は環境変数から。値が全角括弧で囲まれて渡ってくることが
   あるので `.strip("（）()")` で防御する）。0件なら何もせず終了する。

3. **本人の対象週の実績（事実）を集計する**
   実績DBから対象週・本人の行を取得し、訪問数・アポ数・商談数・契約数・契約金額を合計する。
   クローザーのみ、商談分析＆アポ分析DBから自アポ／他アポの内訳も出す。
   クーリングオフ等で当週内に契約が取り消された場合は「契約数n件・契約金額n万円
   （うちn件はYYYY-MM-DDにクーリングオフとなり実質0円）」のように事実を隠さず書く。

4. **KPI目標を逆算する**（クローザーのみ。アポインターは対象外）
   - 実行月のMTDで、本人の `予算（万円）`（予算と達成率DBより）・実質売上・契約数（クーリング
     オフ等で取り消されたものを除いた有効契約数）を求める
   - `平均単価` = MTD実質売上 ÷ MTD有効契約数（有効契約数が0なら、後述のチーム平均単価で代用）
   - `残り予算` = 予算 − MTD実質売上
   - `残り週数` = 実行日から当月末までの日数を7で割って切り上げ（最低1）
   - `今週の目標契約数` = `残り予算 ÷ 平均単価 ÷ 残り週数` を切り上げ、**最低1件**とする
     （必ず1件以上に設定する。ユーザー指示）
   - `商談→契約率`・`アポ→商談率`・`訪問→アポ率` は、実行月MTDの本人実績から計算する。
     本人の分母（商談数・アポ数・訪問数）が0で計算できない指標は、同じ指標のチーム全体の
     MTD平均で代用する
   - `必要商談数` = 今週の目標契約数 ÷ 商談→契約率（切り上げ）
   - `必要アポ数` = 必要商談数 ÷ アポ→商談率（切り上げ）
   - `必要訪問数` = 必要アポ数 ÷ 訪問→アポ率（切り上げ）
   - **重要**: 本人の対象週（またはMTD）の訪問数・アポ数が実績上0の「他アポ専任型」
     （他の人が取ったアポでしか商談していないクローザー）の場合、`必要アポ数`・`必要訪問数`の
     行は表示しない（`必要商談数`までで止める）。チーム平均の訪問→アポ率を機械的に当てはめても
     本人が取るべき行動として意味を持たないため（今川さんの実例で確認済み）

5. **月間チーム予算の進捗を集計する（全員向け・共通の1本）**
   実績DBの実行月MTD全行から `実質売上合計` = SUM(契約金額（万円）) − SUM(キャンセル金額（万円）)
   を計算し、`予算と達成率`DBの実行月全行から `予算合計` = SUM(予算（万円）) を計算する。
   達成率 = 実質売上合計 ÷ 予算合計 × 100（%、整数）。

6. **1人1通でLINE送信する**
   `DEAL_LINE_CHANNEL_ACCESS_TOKEN` を使い、`https://api.line.me/v2/bot/message/push` に
   POSTする（`scripts/line_richmenu.py` のurllib直叩きパターンを踏襲）。**1人につき1回の
   push呼び出し**に収める。

   **role='closer' の人**（他アポ専任型は必要アポ数・必要訪問数の行を省略）:
   ```
   【週次実績】〇〇さん（M/D〜M/D）

   ■先週の実績
   訪問数: n件
   アポ数: n件
   商談数: n件（自アポ n件／他アポ n件）
   契約数: n件
   契約金額: n万円（クーリングオフ等があれば注記）

   ■今週のKPI目標（今月の契約目標達成に向けて）
   今週の目標契約数: n件
   　→ 必要商談数: n件（商談→契約率n%＝本人実績/チーム平均で算出）
   　→ 必要アポ数: n件（アポ→商談率n%＝本人実績/チーム平均で算出）※他アポ専任型は省略
   　→ 必要訪問数: n件（訪問→アポ率n%＝本人実績/チーム平均で算出）※他アポ専任型は省略

   ---
   📊 チームMTD予算進捗（YYYY-MM）: n万円 / n万円（達成率n%）
   ```

   **role='appointer' の人**（事実のみ。契約数・契約金額・KPI逆算は出さない）:
   ```
   【週次実績】〇〇さん（M/D〜M/D）

   ■先週の実績
   訪問数: n件
   アポ数: n件
   商談数: n件

   ---
   📊 チームMTD予算進捗（YYYY-MM）: n万円 / n万円（達成率n%）
   ```

7. **今川さんへの管理者サマリー**
   全員への配信が終わったら、今川さん（LINE, line_user_id は `closer_line_users` で
   `closer_name='今川'` の行）へ1通、対象者数・送信成功数・送信失敗があればその一覧を送る。

## 注意事項

- 個人の売上・給与に関わる実数（予算・実質売上）は**チーム合計のみ**を配信する。個人別の
  予算達成率は本人にのみ配信し、他人には見せない（Notion上の個人別データはそのまま
  今川さんが確認できるので、チーム向け配信では集約値のみ扱う）
- Notionの実績DBは日次反映にラグがあることを確認済み（数日分がまとめて事後入力されることが
  ある）。水曜9:00時点で直近の火曜分が未反映のケースはあり得るため、達成率・件数は
  「その時点でNotionに反映されている実績」である旨を前提とする（配信文言で毎回断る必要はない）
- 「今週のやるべきこと」的な定性コメント（MTスライドの「来週の宣言」等）は**自動配信に含めない**。
  MT時点のスナップショットが実態とズレて古い内容のまま届くリスクがあるため（実例で確認済み）
